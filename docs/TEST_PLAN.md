# 测试计划

## 自动检查

运行 `./scripts/run-checks.sh`，覆盖以下 15 项核心场景：

1. 首次安装默认保护值为 20%；
2. 无 App 规则时使用默认保护值；
3. 前台 App 规则覆盖默认保护值；
4. 禁用规则回退默认保护值；
5. 超限时生成只降不升的钳制决策；
6. 用户手动调高时不抢回控制权；
7. App 场景切换时仍执行保护；
8. 等于或低于保护值时不写；
9. 暂停或关闭时不干预；
10. 0...1 边界标准化；
11. 重复 Bundle ID 保留最新规则；
12. 设置持久化；
13. 删除 App 规则后重启不会恢复；
14. 损坏配置回退到默认开启、20% 保护值；
15. 本地事件历史数量受限。

运行 `./scripts/build-app.sh` 验证所有 AppKit/Core Audio 源码均能优化编译、Info.plist 合法且 `.app` 可完成临时签名。运行 `./scripts/ui-smoke-test.sh` 通过 Launch Services 打开通用与 App 规则两个 pane 并生成截图，防止设置窗口崩溃或 pane 尺寸错误。运行 `./scripts/integration-volume-test.sh` 会全程静音，先验证 App 启动时把 82% 压至约 20%，再验证用户手动调到 67% 后不会被抢回，最后无条件恢复原始音量和静音状态。运行 `./scripts/check-performance.sh` 使用隔离配置并关闭保护，验证 App 能常驻、不会改变用户音量，且 5 秒空闲采样 RSS 不超过 80 MB。

## 真机功能用例

| 编号 | 操作 | 预期 |
|---|---|---|
| F01 | 默认保护值 20%，从控制中心手动调到 100% | 保留用户选择的音量，状态显示“已保留手动音量” |
| F02 | 手动音量为 100%，随后切换前台 App | 按新场景保护值自动调低 |
| F03 | 把保护值从 60% 降到 20% | 当前高于 20% 时立即降到约 20% |
| F04 | 把保护值从 20% 提到 80% | 当前音量不自动升高 |
| F05 | 会议 App 规则 100%，音乐 App 规则 55%，由会议切到音乐 | 切换后若当前高于 55%，自动降到约 55% |
| F06 | 暂停 15 分钟并提高音量 | 暂停期间不干预，到时自动恢复并检查 |
| F07 | 关闭保护并提高音量 | 不干预，状态图标显示关闭 |
| F08 | 从内置扬声器切到已处于高音量的蓝牙耳机 | 新设备支持系统音量时按当前规则调低 |
| F09 | 切到不可写音量的 HDMI/外置 DAC | 明确显示“不支持”，不刷通知、不崩溃 |
| F10 | 连续按音量增加键 | 音量随用户输入顺畅变化，不被持续压回，无写入死循环 |
| F11 | 静音后触发检查 | 保持静音，不自动取消静音 |
| F12 | 睡眠后唤醒、拔插耳机 | 重新绑定当前默认设备并执行检查 |
| F13 | 启用登录启动、退出并重新登录 | 无 Dock 图标、无设置窗口，静默驻留菜单栏 |
| F14 | 关闭登录启动并重新登录 | App 不再自动启动，LaunchAgent 文件被移除 |
| F15 | 拒绝通知权限 | 核心音量保护仍正常工作 |
| F16 | 从 Finder 选择一个未运行的 `.app` | 成功创建规则，重复选择不会生成重复项 |
| F17 | 关闭某条 App 规则 | 该规则滑杆禁用，匹配 App 时回退默认保护值 |
| F18 | 从状态栏为当前 App 添加规则 | 直接进入 App 规则 pane，并创建默认 20% 规则 |
| F19 | 在通用与 App 规则 pane 间切换 | 工具栏选中态、窗口标题和窗口尺寸同步更新，无裁切 |
| F20 | 从 Finder 双击 App | 首次启动直接显示设置窗口，并同时出现菜单栏图标 |
| F21 | App 已运行时再次双击 | 复用现有进程并唤起设置窗口，不产生第二个常驻实例 |
| F22 | 在“应用程序”和 Finder 中查看 App | 显示蓝绿色盾牌声波图标，无白色方形底或模糊边缘 |
| F23 | 点击规则行的“移除”，关闭并重新打开设置 | 规则立即消失，重新打开或重启 App 后都不会恢复 |

## 性能与稳定性

- 空闲 30 分钟：CPU 接近 0%，RSS 无持续增长；
- 连续调音量 100 次：无崩溃、无事件监听反馈循环；
- 连续切换输出设备 20 次：旧设备监听移除，新设备状态正确；
- 同一输出设备连续触发 100 次音量事件：设备元数据缓存复用，无重复声道枚举；
- 连续运行 8 小时：历史最多 20 条，内存不随事件数持续增长。

## 视觉与可访问性检查

- macOS 深色/浅色模式下工具栏、分组背景、正文和次要文字对比正常；
- 通用页显示保护状态、当前设备、当前音量、生效保护值和规则来源；
- 手动音量高于保护值时明确显示“已保留手动音量”，不伪装成已经压低；
- 两条及以上规则不再挤压或裁掉通用设置；
- 开关、滑杆、运行中 App 弹出按钮均有辅助功能标签；
- `Command-,` 打开设置，键盘可在工具栏和当前 pane 控件间移动。

## 当前环境限制

当前机器只有 Apple Command Line Tools，没有完整 Xcode 的 `xctest`，因此自动化核心检查使用独立轻量可执行程序。完整 UI 自动化、登录后重启和多种硬件输出设备矩阵仍需安装 Xcode 或按上述真机用例执行。
