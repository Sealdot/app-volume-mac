# 测试计划

## 自动检查

运行 `./scripts/run-checks.sh`，覆盖以下 28 项核心场景：

1. 首次安装默认保护值为 20%；
2. 无 App 规则时使用默认保护值；
3. 前台 App 场景规则覆盖默认保护值；
4. 当前设备规则覆盖默认保护值；
5. 设备类型预设在无精确规则时生效；
6. 场景、设备、类型、默认值的优先级；
7. 禁用规则回退默认保护值；
8. 超限时生成只降不升的钳制决策；
9. 智能模式下用户手动调高时不抢回控制权；
10. 严格模式压回手动超限音量；
11. 耳机离开时优先静音并同步降低音量标量；
12. 静音不可用时回退到指定音量；
13. 耳机之间切换、保护暂停或目标音量已经安全时不执行空操作；
14. 重复 App/设备通知不抢回手动音量；
15. 真实 App/设备变化和系统唤醒仍执行保护；
16. App 场景切换时仍执行保护；
17. 等于或低于保护值时不写；
18. 暂停或关闭时不干预；
19. 0...1 边界标准化；
20. 重复 Bundle ID 保留最新规则；
21. 设备规则去重和设备类型预设补全；
22. 新安装默认启用耳机离开静音和首次引导；
23. 旧设置迁移保持原行为且不重复引导；
24. 设置持久化；
25. 删除 App 规则后重启不会恢复；
26. 损坏配置回退到安全默认值；
27. 本地事件历史数量受限；
28. 旧保护事件迁移为音量降低类型。

运行 `./scripts/build-app.sh` 验证所有 AppKit/Core Audio 源码均能优化编译、Info.plist 合法且 `.app` 可完成临时签名。运行 `./scripts/ui-smoke-test.sh` 通过 Launch Services 打开四个等尺寸设置 pane 和首次引导并生成截图。运行 `./scripts/integration-volume-test.sh` 会全程静音，验证智能模式启动保护且保留手调，再验证严格模式把手调超限音量压回，最后无条件恢复原始音量和静音状态。运行 `./scripts/check-performance.sh` 使用隔离配置并关闭保护，验证 App 能常驻、不会改变用户音量，且 5 秒空闲采样 RSS 不超过 80 MB。

## 真机功能用例

| 编号 | 操作 | 预期 |
|---|---|---|
| F01 | 默认保护值 20%，从控制中心手动调到 100% | 保留用户选择的音量，状态显示“已保留手动音量” |
| F02 | 手动音量为 100%，随后切换前台 App | 按新场景保护值自动调低 |
| F03 | 把保护值从 60% 降到 20% | 当前高于 20% 时立即降到约 20% |
| F04 | 把保护值从 20% 提到 80% | 当前音量不自动升高 |
| F05 | 会议 App 规则 100%，音乐 App 规则 55%，由会议切到音乐 | 切换后若当前高于 55%，自动降到约 55% |
| F06 | 暂停 15 分钟并提高音量 | 暂停期间不干预，到时自动恢复并检查 |
| F07 | 关闭保护并提高音量 | 不干预，状态图标显示关闭 |
| F08 | 从内置扬声器切到已处于高音量的蓝牙耳机 | 新设备支持系统音量时按当前规则调低 |
| F09 | 切到不可写音量的 HDMI/外置 DAC | 明确显示“不支持”，不刷通知、不崩溃 |
| F10 | 连续按音量增加键 | 音量随用户输入顺畅变化，不被持续压回，无写入死循环 |
| F11 | 静音后触发检查 | 保持静音，不自动取消静音 |
| F12 | 睡眠后唤醒、拔插耳机 | 重新绑定当前默认设备并执行检查 |
| F13 | 启用登录启动、退出并重新登录 | 无 Dock 图标、无设置窗口，静默驻留菜单栏 |
| F14 | 关闭登录启动并重新登录 | App 不再自动启动，LaunchAgent 文件被移除 |
| F15 | 拒绝通知权限 | 核心音量保护仍正常工作 |
| F16 | 从 Finder 选择一个未运行的 `.app` | 成功创建规则，重复选择不会生成重复项 |
| F17 | 关闭某条 App 规则 | 该规则滑杆禁用，匹配 App 时回退默认保护值 |
| F18 | 展开状态栏菜单 | 不显示当前 App 规则快捷入口或“立即执行保护”；通过“设置…”统一进入设置页 |
| F19 | 在通用、场景规则、设备和历史 pane 间切换 | 四个 pane 固定等宽等高，窗口不缩放或横跳；工具栏选中态和标题同步更新，无裁切 |
| F20 | 从 Finder 双击 App | 新安装显示首次引导，已完成引导时显示设置窗口；两种情况都同时出现菜单栏图标 |
| F21 | App 已运行时再次双击 | 复用现有进程并唤起设置窗口，不产生第二个常驻实例 |
| F22 | 在“应用程序”和 Finder 中查看 App | 显示蓝绿色盾牌声波图标，无白色方形底或模糊边缘 |
| F23 | 在 App 规则页移除规则，关闭并重新打开规则页 | 存储条数和屏幕行数同时减一，已删除规则不会恢复 |
| F24 | 新安装首次启动 | 显示隐私、保护模式和耳机离开动作引导；完成后不再重复显示 |
| F25 | 智能模式下把系统音量调到保护值以上 | 保留手调并标识“已保留手动音量” |
| F26 | 严格模式下把系统音量调到保护值以上 | 立即降低至当前生效保护值，无反馈循环 |
| F27 | 为当前输出设备设置独立值并重新连接 | 设备 UID/数据源匹配后使用设备值 |
| F28 | 启用无线耳机类型预设，连接无精确规则的新耳机 | 使用无线耳机类型预设 |
| F29 | 同时存在场景、设备和类型规则 | 按场景、设备、类型、默认值的顺序选择第一条启用规则 |
| F30 | 从耳机切换到内置扬声器，动作设为立即静音 | 新输出立即静音，历史记录耳机离开事件 |
| F31 | 从耳机切换到不支持静音但可调音量的设备 | 回退到配置的耳机离开音量，并如实显示兼容性 |
| F32 | 从一副耳机切换到另一副耳机 | 不触发耳机离开静音 |
| F33 | 当前 Core Audio 设备不变，但数据源从耳机切回扬声器 | 重新分类数据源并执行耳机离开保护 |
| F34 | 打开历史页并清除 | 显示最近 20 次事件；清除后本地存储和界面同时为空 |

## 性能与稳定性

- 空闲 30 分钟：CPU 接近 0%，RSS 无持续增长；
- 连续调音量 100 次：无崩溃、无事件监听反馈循环；
- 连续切换输出设备 20 次：旧设备监听移除，新设备状态正确；
- 同一输出设备连续触发 100 次音量事件：设备元数据缓存复用，无重复声道枚举；
- 连续运行 8 小时：历史最多 20 条，内存不随事件数持续增长。

## 视觉与可访问性检查

- macOS 深色/浅色模式下工具栏、分组背景、正文和次要文字对比正常；
- 通用页显示保护状态、当前设备、当前音量、生效保护值和规则来源；
- 通用、场景规则、设备和历史页使用相同尺寸、24pt 外边距、分区标题、圆角卡片和底部说明样式；
- 手动音量高于保护值时明确显示“已保留手动音量”，不伪装成已经压低；
- 两条及以上规则不再挤压或裁掉通用设置；
- 开关、滑杆、运行中 App 弹出按钮均有辅助功能标签；
- `Command-,` 打开设置，键盘可在工具栏和当前 pane 控件间移动。

## 当前环境限制

当前机器只有 Apple Command Line Tools，没有完整 Xcode 的 `xctest`，因此自动化核心检查使用独立轻量可执行程序。完整 UI 自动化、登录后重启和多种硬件输出设备矩阵仍需安装 Xcode 或按上述真机用例执行。
