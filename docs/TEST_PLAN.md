# 测试计划

## 自动检查

运行 `./scripts/run-checks.sh`，覆盖以下 12 项核心场景：

1. 首次安装默认上限为 20%；
2. 无 App 规则时使用默认上限；
3. 前台 App 规则覆盖默认上限；
4. 禁用规则回退默认上限；
5. 超限时生成只降不升的钳制决策；
6. 等于或低于上限时不写；
7. 暂停或关闭时不干预；
8. 0...1 边界标准化；
9. 重复 Bundle ID 保留最新规则；
10. 设置持久化；
11. 损坏配置回退到默认开启、20% 上限；
12. 本地事件历史数量受限。

运行 `./scripts/build-app.sh` 验证所有 AppKit/Core Audio 源码均能优化编译、Info.plist 合法且 `.app` 可完成临时签名。运行 `./scripts/integration-volume-test.sh` 会先静音、将音量标量临时调到 82%、验证 App 自动压至约 20%，最后无条件恢复原始音量和静音状态。运行 `./scripts/check-performance.sh` 使用隔离配置并关闭保护，验证 App 能常驻、不会改变用户音量，且 5 秒空闲采样 RSS 不超过 80 MB。

## 真机功能用例

| 编号 | 操作 | 预期 |
|---|---|---|
| F01 | 默认上限 20%，从控制中心调到 100% | 音量回到约 20%，菜单显示最近保护事件 |
| F02 | 音量为 15%，上限 20% | 音量不变 |
| F03 | 把上限从 60% 降到 20% | 当前高于 20% 时立即降到约 20% |
| F04 | 把上限从 20% 提到 80% | 当前音量不自动升高 |
| F05 | 会议 App 规则 100%，音乐 App 规则 55%，由会议切到音乐 | 切换后若当前高于 55%，自动降到约 55% |
| F06 | 暂停 15 分钟并提高音量 | 暂停期间不干预，到时自动恢复并检查 |
| F07 | 关闭保护并提高音量 | 不干预，状态图标显示关闭 |
| F08 | 从内置扬声器切到已处于高音量的蓝牙耳机 | 新设备支持系统音量时按当前规则调低 |
| F09 | 切到不可写音量的 HDMI/外置 DAC | 明确显示“不支持”，不刷通知、不崩溃 |
| F10 | 连续按音量增加键 | 不能长时间保持在上限之上，无写入死循环 |
| F11 | 静音后触发检查 | 保持静音，不自动取消静音 |
| F12 | 睡眠后唤醒、拔插耳机 | 重新绑定当前默认设备并执行检查 |
| F13 | 启用登录启动、退出并重新登录 | 无 Dock 图标、无设置窗口，静默驻留菜单栏 |
| F14 | 关闭登录启动并重新登录 | App 不再自动启动，LaunchAgent 文件被移除 |
| F15 | 拒绝通知权限 | 核心音量保护仍正常工作 |

## 性能与稳定性

- 空闲 30 分钟：CPU 接近 0%，RSS 无持续增长；
- 连续调音量 100 次：无崩溃、无事件监听反馈循环；
- 连续切换输出设备 20 次：旧设备监听移除，新设备状态正确；
- 连续运行 8 小时：历史最多 20 条，内存不随事件数持续增长。

## 当前环境限制

当前机器只有 Apple Command Line Tools，没有完整 Xcode 的 `xctest`，因此自动化核心检查使用独立轻量可执行程序。完整 UI 自动化、登录后重启和多种硬件输出设备矩阵仍需安装 Xcode 或按上述真机用例执行。
